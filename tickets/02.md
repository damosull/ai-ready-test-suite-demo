# 02 · Draft order: staff can delete a draft they no longer need

**Type:** Test coverage · **Area:** Orders / Drafts · **Priority:** Low

## Context

Drafts pile up: a customer abandons a phone order, or staff start one in the wrong channel.
Staff delete a draft from the draft page's menu, after a confirmation. We have no e2e coverage
of this; if deletion silently failed, the drafts list would keep filling with orders nobody can
get rid of.

## What to cover

1. Start a draft order in the USD channel.
2. Delete it from the draft's menu and confirm.
3. The draft is gone.

## Acceptance criteria

- [ ] After confirming, staff are taken back to the drafts list.
- [ ] Opening the deleted draft's address again shows the "page was not found" screen, not the
      draft.

## Notes

- Use the existing draft-order page object to start the draft.
- No new test infrastructure needed.
